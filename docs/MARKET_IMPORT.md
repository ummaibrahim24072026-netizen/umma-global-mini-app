# Импорт Market / B2B

Администратор склада: «Ещё → Администрирование → склад Market → Импорт CSV».

1. Выбрать действующего поставщика и категорию по умолчанию.
2. Экспортировать таблицу Excel в CSV UTF-8 и выбрать файл (до 100 строк за загрузку).
3. Проверить предпросмотр: новый черновик / обновление закупочной цены / ошибка.
4. Явно подтвердить импорт. История доступна на той же вкладке.
5. Открыть «Товары», проверить состав, происхождение и фотографии, назначить розничную цену и включить нужные карточки/предложения.

Заголовки CSV:

```csv
name_ru,name_en,name_vi,supplier_sku,gtin,sale_mode,measure,fixed_quantity,purchase_price_vnd
```

Обязательны name_ru и supplier_sku. Другие поля могут быть пустыми; sale_mode по умолчанию piece, measure — pcs. Модели: piece, set, fixed_weight, individual_weight. Весовые модели используют g, размер упаковки — целое число граммов. Для set/fixed_weight обязателен fixed_quantity. GTIN сохранять текстом с ведущими нулями. Цена закупки — целые VND, необязательна. Не вводить выдуманные значения вместо отсутствующих данных.

Сертификат не является обязательным полем. Импорт не присваивает халяль-статус, не создаёт остатки и не меняет цену уже опубликованного товара/заказа. Новые карточки неактивны, предложения не опубликованы. «Проверено UMMA» означает административную проверку состава и происхождения, а не заявление о сертификации. Сертификат в интерфейсе пока отмечается как не предоставленный.

Сопоставление выполняется по коду производителя и SKU выбранного поставщика. Неоднозначные совпадения, смена GTIN или модели упаковки требуют ручной проверки. Существующему товару обновляется только связь с поставщиком и закупочная цена; его публичная карточка не перезаписывается.

Фотографии из CSV не загружаются: для них необходимо право использования. XLSX непосредственно не читается — сначала экспортировать в CSV. Партнёрский API MM, автоматическая закупка, ступенчатые оптовые цены и B2B-счета этим этапом не добавляются; B2B продолжает существующее согласование поставок через заявки.

## Развёртывание

Применить `supabase/proposals/market-import.sql` после текущего Market release, затем опубликовать frontend. SQL добавляет таблицы заданий импорта/связей поставщика и обработку действий import_stage/import_commit/import_list через существующий service-only market_operation. Edge Function заменять не требуется. Новые таблицы закрыты от прямого доступа anon/authenticated. Подтверждение транзакционное; повторы идемпотентны. Фиктивные товары в production не создаются.

Проверки: `npm test`; дополнительные гонки независимых сессий — `scripts/qa-market-native.mjs` в изолированном PostgreSQL CI. Откат frontend скрывает вкладку импорта; дополнительные таблицы сохранять для истории, а исходное определение market_operation восстанавливать из приватной резервной копии при необходимости. Данные Cafe и существующие операции склада не удалять.
