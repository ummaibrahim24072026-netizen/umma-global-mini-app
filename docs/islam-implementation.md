# UMMA GLOBAL — Ислам: Коран и Сунна

## Результат и границы готовности

Модуль встроен в существующую Telegram Mini App. Готовы расчётные функции, интерфейсы библиотеки и пошаговых уроков, синхронизация закладок через проверенную Telegram-личность, редакционный процесс и серверные напоминания. Существующий Коран используется без копирования его базы.

**Полное религиозное наполнение ТЗ не завершено.** В закрытой редакции подготовлены 60 исходных записей хадисов, 157 переводов RU/EN/VI и 9 черновых подборок для уроков. Это исходный материал для проверки, а не готовый полный курс. Он не опубликован пользователям. Нет назначенного компетентного рецензента; программная проверка не заменяет его заключение. Полные руководства по омовению, обязательным и дополнительным молитвам, дуа, историческим и богословским темам требуют дальнейшей редакционной подготовки и утверждения.

## Пользовательский путь

Главная → «Ислам» → Кибла, расписание, обучение, Коран, хадисы, очищение, дополнительные молитвы, дуа, основы и мазхабы.

Кибла рассчитывает начальный азимут большой окружности на координаты Каабы 21.4225 / 39.8262. Для Нячанга около 288.26° от истинного севера. По умолчанию показан статический азимут. В Telegram 8.0+ используется нативный DeviceOrientation с запросом абсолютных данных и переводом радиан в градусы; вне поддерживаемого SDK — браузерный API. Живой режим требует разрешения, абсолютного датчика и введённой поправки к истинному северу; относительные, неточные и устаревшие данные отклоняются. Телефон нужно держать горизонтально. Склонение автоматически не определяется.

Расписание использует локально поставляемую Adhan 4.4.3 (MIT), пять молитв и отдельный восход, следующий намаз, отсчёт, день/месяц, IANA-зоны и переходы времени. Доступны MWL, Karachi, Egyptian, NorthAmerica, Singapore, длина тени Асра 1/2 и поправки ±60 целых минут. MWL 18°/17° по умолчанию не является утверждённым расписанием мечети Нячанга. Высокие широты отмечаются, полярный расчёт без решения явно недоступен. Для GPS часовой пояс нужно проверить вручную.

Библиотека выдаёт только опубликованные материалы: источник, издание, арабский текст, доступный перевод, пояснение и доказательства отделены друг от друга. Для уроков предусмотрены варианты Сунны и пошаговый режим. Закладки синхронизируются через сервер. Копирование и отправка используют текст с источником. Непроверенные тексты не переводятся автоматически.

До утверждения собственных материалов показываются понятные статусы и отдельные ссылки на публикации HadeethEnc. Это переходы к внешнему издателю, не утверждение курса UMMA. Если вьетнамского перевода выбранной внешней записи нет, ссылка явно помечена EN.

Опубликованные прочитанные материалы кешируются на устройстве на срок до 24 часов с отметкой времени и предупреждением об офлайн-копии. При подключении материал проверяется снова. После ответа об отзыве или исключения из свежего каталога копия удаляется. Мгновенный отзыв на полностью отключённом устройстве технически невозможен.

## Telegram и личные данные

`islam-service` самостоятельно проверяет подпись Telegram initData; ID из тела запроса не считается личностью. Закрытые Telegram-настройки и закладки доступны только серверу. Клиент не получает сервисных ключей, не может назначить редактора или рецензента. Старые Auth-таблицы первого этапа оставлены без подключения к Telegram, их доступ по-прежнему ограничен RLS.

Обычные координаты компаса/расписания находятся только в памяти сеанса. Для напоминаний пользователь отдельно разрешает сообщения бота и сохранение выбранного места на сервере. Настройки показывают сохранённое место; есть отдельное действие взять место и метод текущего расписания. При отключении координаты очищаются, ожидающие задания отменяются. Сообщение, уже находящееся в отправке, может успеть прийти.

Пользователь выбирает молитвы, минуты до начала, уведомление в момент начала и обычную/беззвучную отправку. Звук зависит от Telegram и телефона; воспроизведение азана не обещается. Уведомления используют серверное время, а не таймер закрытой Mini App.

## Сервер и очередь

Развёрнуты `islam-service` и `islam-worker`. Задание `umma-prayer-reminders` выполняется каждую минуту. Служебный токен имеет ограниченный срок, подпись HMAC и одноразовый nonce; анонимный доступ отклоняется.

Очередь уникальна по пользователю, местной дате, молитве, типу напоминания и версии настроек. Обновление параметров отменяет старые задания. Захват заданий использует `FOR UPDATE SKIP LOCKED` и аренду; старые сообщения не рассылаются задним числом. При блокировке бота подписка отключается. На явный Telegram rate limit предусмотрен ограниченный повтор. При неопределённом результате отправки автоматического повтора нет: Bot API не предоставляет ключ идемпотентности, поэтому нельзя обещать строго «ровно один раз». Старые задания удаляются через семь дней.

## Редакционный процесс

`draft → review → approved → published`. Публичный клиент не может писать тексты и рецензии. Утверждение привязано к SHA-256 точной ревизии и семи проверкам: первоисточники, арабский текст, перевод, достоверность/контекст, объяснение, разногласия, финальное утверждение. Каждый шаг требует доказательства. Изменение дочерних записей повышает ревизию; редактирование утверждённых материалов требует возврата в draft. Снятие хадиса с публикации возвращает зависимые уроки в draft.

Суперадминистратор может готовить материалы и публиковать уже утверждённое, но не получает автоматически права религиозного рецензента. Рецензент назначается отдельно с именем, квалификацией и ссылкой, подтверждающей личность/основание назначения. Автор не может утвердить собственный материал. При назначении нельзя придумывать сведения об учёном или автоматически подписывать его именем.

Исходники подготовлены из официальных выгрузок HadeethEnc: RU v2.25.0, EN v1.25.0, VI v1.19.0. Арабский текст и переводы не перефразированы. Сохранены версии, ссылки и сведения оригинала. Номера HadeethEnc не выдаются за номера аль-Бухари/Муслима: первичная нумерация требует отдельной сверки. Рецензий и утверждений при импорте не создавалось.

## Проверки

- Полный `npm test`: кафе, доставка, оплата, Market, B2B, Коран и модуль Ислама.
- Новые расчётные/UI-тесты: геометрия Киблы, сутки, DST, високосный месяц, Аср, поправки, полярный отказ, абсолютные датчики, очистка при остановке, навигация, языки.
- Библиотека: безопасный вывод текста, варианты и шаги, закладки, офлайн-копии, удаление отозванной копии, явное согласие на напоминания.
- Изолированный PostgreSQL с настоящим pgcrypto: RLS, роли, публикация точной ревизии, независимый рецензент, согласие, удаление координат, захват очереди, отмена старых заданий, HMAC и защита от повтора.
- Edge-тесты: проверенная подпись, запрет подмены actor, отказ неавторизованным редакторам и отсутствие автоматических прав рецензента у администратора.
- Production smoke: публичный каталог HTTP 200 без черновиков; поддельная Telegram-сессия HTTP 401; корректно подписанный worker HTTP 200; повтор токена отклоняется. При проверке подписчиков не было, сообщений никому не отправлено.

**Не проверены на реальном устройстве:** Telegram Android/iOS, физические датчики, реальное получение сообщения после добровольного подключения пользователем. Не выполнена местная сверка расписания Нячанга. Эти пункты нельзя отмечать пройденными по тестовым датчикам и HTTP-проверкам.

## Файлы и воспроизведение

- `js/islam/`: расчёты, основной экран, API, библиотека/редакция и напоминания.
- `css/islam.css`, `index.html`, `js/core/navigation.js`, `js/core/native-shell.js`: оформление и навигация.
- `supabase/functions/islam-service/`, `supabase/functions/islam-worker/`: серверные обработчики и закреплённая библиотека расчётов.
- `supabase/proposals/islam-foundation.sql`, `islam-runtime.sql`, `islam-editor.sql`, `islam-cron.sql`: применённая схема, шлюз и расписание. Последовательность: foundation → runtime → editor → развёртывание функций → smoke → cron.
- `scripts/qa-islam*.mjs`: автоматические проверки.
- `scripts/import-islam-sources.py`, `scripts/prepare-islam-lessons.py`: подготовка закрытых черновиков из официальных выгрузок; чтение XLSX требует openpyxl. Скрипты не утверждают и не публикуют тексты. SQL импорта не размещается в общедоступных assets.

## Что требуется для полного выполнения исходного ТЗ

1. Назначить действительного компетентного рецензента, сверить первичные номера и издания.
2. Завершить полный курс намаза: условия, пять молитв, все ракааты, произносимое, транслитерации, варианты и доказательства; подготовить очищение, дополнительные молитвы, дуа, основы и исторические темы. Девять исходных подборок этот объём не заменяют.
3. Пройти редакционный процесс и опубликовать утверждённые материалы.
4. Сверить Нячанг с местной мечетью и пройти реальные проверки Android/iOS, компаса и получения напоминания.
