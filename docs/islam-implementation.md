# UMMA GLOBAL — Ислам: Коран и Сунна

## Статус реализации

Этап 1 реализован в существующей Mini App. Это не завершение всего ТЗ.

- Вход «Ислам» на главной и в каталоге направлений.
- Десять подразделов; учебные подразделы явно обозначают подготовку материалов.
- Кибла: начальный азимут большой окружности, координаты Каабы 21.4225 / 39.8262. Для Нячанга около 288.26° от истинного севера.
- Статический режим по умолчанию. Живой режим только после пользовательского разрешения, ввода поправки севера и получения абсолютных данных. Относительные, неточные и устаревшие показания не используются.
- Компас рассчитан на горизонтальный телефон. Калибровка описана; магнитное склонение автоматически не вычисляется. Нельзя считать аппаратный север истинным без сверки.
- Астрономические расчёты Adhan 4.4.3 (MIT), поставляются локально, без CDN. Пять молитв и отдельный восход, следующий намаз, отсчёт, последний солнечный/молитвенный рубеж, дата и месяц.
- MWL 18°/17° по умолчанию — это не утверждённое расписание мечети Нячанга. Доступны Karachi, Egyptian, NorthAmerica, Singapore; тень Асра 1 или 2, поправки −60…60 целых минут для каждого события.
- IANA-зона выбирается для места, отдельно от часового пояса телефона; летнее время форматируется через Intl. При GPS зона автоматически не определяется: нужно проверить её вручную.
- Высокие широты: доля ночи по углу, видимое предупреждение; полярный день/ночь без решения дают явный отказ расчёта.
- Геокоординаты остаются в памяти текущего сеанса. LocalStorage содержит только ID выбранного города, метод, правило Асра и поправки. При следующем запуске произвольное место нужно задать снова.
- Готовый Коран открывается через `ummaQuran.open`; база Корана не копируется.
- RU/EN/VI для нового модуля; арабские первоисточники не переводятся автоматически.

## Основа базы / этапы 2–4

`supabase/proposals/islam-foundation.sql` — применено в проекте Umma Global 19.10.2026 через миграцию `islam_foundation`: 14 новых таблиц, только добавления. Публичная запись хадисов и чтение рецензий проверены как запрещённые. Заказы, кафе, маркет и существующий Коран не меняются.

Нормализованные уроки, шаги, варианты Сунны, доказательства, хадисы, переводы, оценки достоверности, мнения учёных и редакционные рецензии. В библиотеку не добавлены тестовые или сгенерированные религиозные тексты.

Публичное чтение разрешено только для опубликованного содержания. Запись текстов и рецензий — только доверенной серверной стороне. Для публикации требуется рецензия именно на SHA-256 текущей версии, имя и квалификация рецензента, семь положительных проверок. Каждый шаг урока должен иметь доказательство. Для хадиса нужен русский перевод с источником и сведениями об использовании. Связанные хадисы должны быть опубликованы. Редактировать дочерние записи можно только после возврата материала в draft; изменение повышает ревизию и делает старое утверждение неприменимым.

Состояния: draft → review → approved → published. RLS не позволяет клиенту назначить себя редактором. Рецензия не подменяет реального компетентного специалиста; его подпись нельзя генерировать автоматически.

Таблицы пользовательских настроек и закладок ограничены `auth.uid()`. Текущая авторизация Mini App основана на проверке Telegram initData сервером и не означает наличие Supabase Auth-сессии. Поэтому эти таблицы пока не подключены к пользовательскому интерфейсу. Для следующего этапа нужен серверный адаптер проверенной Telegram-личности; нельзя подставлять ID из `initDataUnsafe` в политику доступа или открывать таблицы всем.

## Что ещё требуется по ТЗ

1. Этап 2: полный интерфейс учебных шагов, пять страниц молитв, омовение, переводы и транслитерации. Подготовка и независимая религиозная проверка материалов.
2. Этап 3: импорт первоисточников с разрешёнными условиями использования; сверка изданий и номеров; редакторский интерфейс, поиск и выдача опубликованной библиотеки, закладки и офлайн-кеш с отзывом снятых публикаций.
3. Этап 4: дополнительные молитвы, зикры, дуа, основы, исторические и богословские статьи с источниками и рецензиями.
4. Этап 5: добровольное подключение Telegram-бота, подтверждённый chat ID, серверная очередь и планировщик с уникальностью (пользователь, дата места, молитва, тип уведомления), повторными попытками, отменой при изменении настроек, отслеживанием ошибок и отключением после блокировки бота. Открытая Mini App не используется как фоновой планировщик. Произвольный звук Telegram Bot API не гарантирует — доступны обычная/беззвучная отправка; это нужно явно объяснить в настройках.
5. Местная сверка Нячанга; реальные Telegram Android/iOS и датчики; проверка интерфейса на узких экранах.

## Проверка

`npm run test:islam` проверяет геометрию, диапазоны времени для Нячанга, полярный отказ, тень Асра, поправки, неверные даты, сутки и переход летнего времени, следующий Фаджр, абсолютные датчики, включение/остановку компаса, календарь и високосный февраль, переход в Коран, локализацию и отсутствие сохранённых GPS-координат.

Изолированный PostgreSQL (PGlite) проверяет применение SQL, 14 таблиц с RLS, блокировку публикации без семи проверок текущей версии, необходимость доказательств, отзыв старой рецензии после изменения, недоступность черновиков и рецензий для anon, запрет публичной записи и изоляцию пользователей.

`npm test` — полный существующий набор регрессионных проверок кафе, доставки, оплаты, маркета, B2B, Корана и нового модуля. Аппаратные датчики в автоматических тестах имитируются. Проверка на реальном телефоне этим не заменяется.
